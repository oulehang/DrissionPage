# 表情包生成多任务真并发设计

## 目标

将当前只能运行一个表情包生成任务的本地 Web 工具改造成多任务系统：

- 最多同时运行 10 个生成任务。
- 每个任务使用独立 ChatGPT 标签页，共享同一浏览器登录状态。
- 任务的参数、状态、日志、生成结果和输出目录互相隔离。
- 提供任务列表以及查看、停止、重试、删除、下载和同步微信等操作。
- 单个任务失败、停止或标签页关闭时，不影响其他任务。

## 当前实现限制

当前 `chatgpt_image_web_app.py` 使用单例 `STATE` 保存全部运行状态，并由单个
`ChatGPTWebClient` 控制一个页面。启动生成、搜索热门主题、重连和同步微信时，
接口通过全局忙碌状态互斥，任何任务运行期间再次启动都会返回 HTTP 409。

图片预处理目录、历史记录、下载和前端轮询也都只面向一个“当前任务”，因此不能
仅通过增加线程数量实现安全并发。

## 方案选择

采用单浏览器进程、多标签页、多线程架构。

每个生成任务创建独立 `ChromiumTab` 和独立任务客户端。所有标签页共享浏览器用户
配置和 ChatGPT 登录状态，但不会共享对话页面、任务状态或输出目录。DrissionPage
原生支持不同线程分别操作不同的 `ChromiumTab`。

不采用以下方案：

- 多个独立浏览器进程：同一用户配置目录不适合被多个 Chromium 进程并发使用，
  分离配置又会增加登录和资源成本。
- 多进程任务服务：隔离更强，但需要进程通信、任务数据库和浏览器配置管理，对
  当前本地单文件工具改造过重。

## 核心组件

### `TaskManager`

负责所有任务的注册、查询、调度和持久化，取代全局单任务 `STATE`。

主要职责：

- 保存 `task_id -> GenerationTask` 映射。
- 维护最大并发数 `max_concurrency = 10`。
- 创建任务并决定立即运行或进入等待队列。
- 在运行任务结束后自动调度下一个排队任务。
- 提供任务列表摘要和单个任务完整快照。
- 处理停止、重试、删除和服务重启后的状态恢复。
- 管理共享浏览器实例，但不让任务共享标签页。
- 使用锁保护任务映射和调度状态，任务内部数据由任务自己的锁保护。

### `GenerationTask`

表示一个完整且隔离的表情包生成任务。

主要字段：

- `id`：不可变任务标识。
- `name`、`theme`、`created_at`、`updated_at`。
- 原始生成参数：模式、提示词风格、模板、含义词、参考图及参考图模式。
- `state`、`done`、`total`、`current`、`error`。
- `log`、`images`、`metadata`、`hot_theme`。
- `output_dir`：`chatgpt_images/tasks/<task_id>/`。
- `worker`、`tab`、任务专属 ChatGPT 客户端。
- `cancel_event`：协作式停止信号。
- `hidden`：运行中删除时先从列表隐藏。

任务不能直接修改其他任务，也不能通过全局当前任务读取图片、元数据或日志。

### 任务专属 ChatGPT 客户端

现有 `ChatGPTWebClient` 改为支持传入一个已有 `ChromiumTab`，同时保留原先创建
浏览器页面的兼容路径。

`TaskManager` 持有共享 `ChromiumPage`，每个任务通过 `new_tab(CHATGPT_URL)`
获得独立标签页，再创建只操作该标签页的客户端。客户端的图片记录和已见图片集合
也必须是实例级数据。

## 状态模型

任务状态包括：

- `queued`：并发槽位已满，等待调度。
- `running`：正在生成文案或图片。
- `stopping`：已收到停止请求，等待当前浏览器操作结束。
- `stopped`：协作式停止完成。
- `done`：全部生成步骤完成。
- `error`：任务运行失败或标签页意外关闭。
- `syncing`：正在同步该任务到微信表情开放平台。
- `interrupted`：服务重启前仍处于活动状态，恢复后需要人工重试。

主要转换：

```text
queued -> running -> done
queued -> stopped
running -> stopping -> stopped
running -> error
running -> interrupted
stopped/error/interrupted -> queued 或 running（重试）
done -> syncing -> done
syncing -> error 或 done
```

重试复用原任务参数，并新建一次执行记录。进度、当前步骤、错误和本次日志会重置，
旧图片保留在任务目录中；新生成文件使用新的执行子目录，避免覆盖。

## 并发与取消

最多允许 10 个处于 `running` 的生成任务。第 11 个及之后的任务进入 `queued`，
任一运行任务结束后由调度器自动补位。

停止使用协作式取消：

- 在生成文案前、每张图片发送前、图片处理前后检查 `cancel_event`。
- 已经进入的 `bot.ask()` 不强杀线程，也不与浏览器驱动争抢底层连接。
- 当前浏览器操作返回后，任务转为 `stopped` 并释放并发槽位。
- 排队任务可立即取消并转为 `stopped`。

标签页被用户关闭或连接失效时，仅对应任务进入 `error`。重试时创建新标签页。

## 文件隔离与持久化

目录结构：

```text
chatgpt_images/
  tasks/
    <task_id>/
      task.json
      references/
      runs/
        <run_id>/
          source/
          wechat_ready/
```

`task.json` 保存任务参数、状态摘要、元数据、图片清单和执行记录。写入采用临时文件
加原子替换，避免多个线程写坏 JSON。

服务启动时扫描任务目录：

- `done`、`stopped`、`error` 任务原样恢复。
- `queued`、`running`、`stopping`、`syncing` 转为 `interrupted`。
- 不自动恢复浏览器操作，用户可从列表点击重试。

删除任务默认只从列表移除并保留生成文件。运行中的任务先标记隐藏并请求停止，
停止完成后从内存任务映射移除。设计不提供物理删除输出文件，避免误删。

## API 设计

### 创建与查询

- `POST /api/tasks`：创建生成任务，返回任务摘要。
- `GET /api/tasks`：返回任务列表摘要，不携带完整日志和图片数据。
- `GET /api/tasks/<task_id>`：返回单个任务完整详情。

### 生命周期操作

- `POST /api/tasks/<task_id>/stop`
- `POST /api/tasks/<task_id>/retry`
- `DELETE /api/tasks/<task_id>`
- `POST /api/tasks/<task_id>/sync_wechat`
- `GET /api/tasks/<task_id>/download`

旧的 `/api/start` 和 `/api/status` 可在迁移期映射到新接口，但前端完成迁移后不再
依赖全局当前任务语义。

错误响应至少区分：任务不存在、状态不允许、并发操作冲突、浏览器连接失败和输入
校验失败。

## 微信同步约束

生成任务可同时运行，但微信平台同步全局只允许一个任务执行。原因是同步会操作同一
浏览器登录状态下的微信提交页面，多任务同时填写和上传容易混用表单。

同步锁只限制微信同步，不占用 10 个 ChatGPT 生成槽位；其他生成任务继续运行。
同步始终读取指定任务的元数据和图片路径，不能读取当前界面选中的其他任务。

## 前端设计

采用已确认的“左侧任务列表 + 右侧任务详情”布局。

### 左侧任务列表

- 顶部提供“新建任务”。
- 每项显示任务名称、状态、进度、更新时间和错误标记。
- 支持快速切换选中任务。
- 排队、停止、失败、完成和同步状态使用不同视觉标识。

### 右侧任务详情

- 显示任务参数、进度、当前步骤和错误。
- 显示任务专属日志、生成文案和图片画廊。
- 根据状态提供停止、重试、删除、下载全部和同步微信按钮。
- 新建任务表单复用现有主题、模式、提示词风格、参考图和模板字段。

前端周期性请求 `/api/tasks`，只请求选中任务的完整详情。这样 10 个任务同时运行时，
不会在每次轮询中传输所有任务的完整日志和图片清单。

页面刷新后恢复任务列表，并优先保持上次选中的任务；如果该任务已删除，则选择列表
第一项。

## 异常处理

- 每个任务工作线程捕获自身异常并写入任务错误，不向其他任务传播。
- 任务的文件处理失败只使该任务进入 `error`。
- 标签页失效时给出可操作错误，重试时创建新标签页。
- 任务持久化失败记录到服务日志，并保留内存状态；不能因此停止其他任务。
- 并发调度器使用 `finally` 释放槽位，避免异常导致永久占用。
- 单个任务的日志限制保留最近若干条，持久化执行记录可保留完整日志。
- API 只返回用户可理解的错误信息，详细异常写入任务日志。

## 测试策略

使用模拟浏览器客户端和模拟标签页，不依赖真实 ChatGPT。

单元测试覆盖：

- 任务状态转换合法性。
- 创建 11 个任务时只运行 10 个，第 11 个排队。
- 任一任务结束后排队任务自动启动。
- 每个任务拥有不同标签页、状态对象和输出目录。
- 单个任务失败不影响其他任务。
- 排队任务停止和运行任务协作式停止。
- `error`、`stopped`、`interrupted` 任务重试。
- 删除任务时隐藏、停止和保留文件的行为。
- 重启恢复时活动状态转为 `interrupted`。
- 微信同步全局互斥但不阻塞生成任务。

API 测试覆盖：

- 创建、列表和详情查询。
- 停止、重试、删除、下载和同步。
- 不存在任务、非法状态和无效输入。
- 列表摘要不返回完整日志和图片内容。

现有提示词、参考图和批量生成测试继续保留，并将依赖的全局状态替换为显式任务对象
或测试夹具。

## 验收标准

- 可连续创建至少 11 个任务，前 10 个同时进入生成，第 11 个显示排队。
- 同时运行的任务分别操作不同 ChatGPT 标签页。
- 任一任务的进度、日志、图片和错误不会出现在其他任务中。
- 停止、失败或删除一个任务不会中断其他任务。
- 页面刷新后可查看任务列表和已有结果，重启中断任务可重试。
- 每个任务可独立下载全部图片，并可选择完成任务同步微信。
- 自动化测试无需访问 ChatGPT 即可验证调度、隔离和 API 行为。
